5: [Normal] 1. EXECUTIVE SUMMARY
6: [Normal] ApexFormz currently operates as a real-time biomechanical coaching platform built around:
7: [Normal] browser-based MediaPipe pose extraction,
8: [Normal] a Next.js user interface,
9: [Normal] Node.js/Express orchestration,
10: [Normal] Socket.IO real-time transport,
11: [Normal] a FastAPI AI-analysis service,
12: [Normal] static pose analysis,
13: [Normal] dynamic phase-based movement analysis,
14: [Normal] nearest-neighbour expert-frame matching,
15: [Normal] DTW trajectory analysis,
16: [Normal] kinetic-chain validation,
17: [Normal] signal filtering,
18: [Normal] ST-GCN Action Quality Assessment,
19: [Normal] PostgreSQL persistence,
20: [Normal] gamification,
21: [Normal] and social training systems.
22: [Normal] The current platform already separates static and dynamic movement analysis and maintains movement definitions through sport/movement configuration.
However, ApexFormz is now moving from a controlled prototype architecture toward a real-world multi-sport platform.
23: [Normal] The next architectural challenge is domain isolation.
24: [Normal] Sports may contain superficially similar body configurations while requiring very different biomechanical interpretation.
25: [Normal] Examples:
26: [Normal] badminton overhead forehand vs tennis serve,
27: [Normal] badminton forehand vs tennis forehand,
28: [Normal] cricket bowling vs throwing,
29: [Normal] boxing rotation vs racquet-sport rotation,
30: [Normal] Taekwondo kicking vs football kicking.
31: [Normal] A universal movement reference database can therefore create semantic ambiguity even when the pose geometry itself is correctly measured.
32: [Normal] The V2 architecture solves this through hierarchical intelligence:

52: [Normal] The Universal Human Motion Engine understands the human body.

55: [Normal] The Coaching Engine explains what should change.

57: [Normal] This modular architecture becomes the foundation for future ApexFormz sports.
59: [Normal] 2. PRODUCT VISION
60: [Normal] ApexFormz should become:
61: [Normal] A modular human-performance intelligence platform capable of understanding how an athlete moves, interpreting that movement within the correct sport, evaluating it against validated expert execution, and delivering real-time personalized coaching.
62: [Normal] The platform should not merely answer:
63: [Normal] “Where is the athlete's knee?”
64: [Normal] It should eventually answer:
65: [Normal] “During the acceleration phase of your badminton smash, your shoulder initiated before your hip rotation, reducing kinetic-chain efficiency. On your previous eight reps, this sequencing problem occurred six times.”
66: [Normal] The long-term ApexFormz intelligence hierarchy is therefore:
67: [Normal] Layer 1 — Perception
68: [Normal] What does the camera observe?
69: [Normal] Layer 2 — Human Motion
70: [Normal] What is the body physically doing?
71: [Normal] Layer 3 — Sport Understanding
72: [Normal] What does this body movement mean within badminton, tennis, cricket, Taekwondo, etc.?
73: [Normal] Layer 4 — Movement Understanding
74: [Normal] Which exact movement and phase is being performed?
75: [Normal] Layer 5 — Biomechanical Evaluation
76: [Normal] How does this execution differ from accepted expert execution?
77: [Normal] Layer 6 — Coaching
78: [Normal] What correction should the athlete make?
79: [Normal] Layer 7 — Athlete Intelligence
80: [Normal] What recurring strengths, weaknesses, improvements and patterns exist for this athlete?
82: [Normal] 3. PROBLEM STATEMENT
83: [Normal] 3.1 Current scaling problem
84: [Normal] The current dynamic architecture supports multiple sports and movements through movement configuration and routing. Dynamic sessions maintain their own state and the FrameMatcher uses expert reference frames for movement comparison.
85: [Normal] This is appropriate for the current stage.
86: [Normal] However, as the reference database grows, the platform needs stronger architectural guarantees that:
87: [Normal] badminton data cannot affect tennis scoring,
88: [Normal] tennis references cannot affect Taekwondo analysis,
89: [Normal] movement-specific rules cannot leak between movements,
90: [Normal] sport-specific biomechanics remain isolated,
91: [Normal] sport-specific models can be developed independently,
92: [Normal] scoring criteria can differ between sports,
93: [Normal] future ML models can use shared representations without sharing incorrect decision boundaries.
94: [Normal] The problem is not simply database size.
95: [Normal] The fundamental problem is semantic contamination.
96: [Normal] A human configuration can be geometrically similar across sports while carrying different biomechanical meaning.

99: [Normal] 4.1 Primary goals

112: [Normal] Support optional automatic sport/movement recognition later.
113: [Normal] Make adding a new sport primarily a plugin/configuration/data task rather than requiring changes to the central analysis engine.
114: [Normal] Build a foundation for longitudinal athlete intelligence.
